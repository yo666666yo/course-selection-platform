## 一、风格选择决策

### 1.1 候选风格矩阵

从教材所列 14 种风格中，按"本系统适配度 × 实现收益"构建决策矩阵：

| 风格 | 适配度 | 变更半径 | 可验证性 | 决策结果 |
|---|---|---|---|---|
| 面向方面 (AOP) | 高 | 小（已有拦截器） | 高 | **已部分采用，继续强化** |
| **事件驱动** | **高** | **中** | **高** | **★ 本次演化目标** |
| 基于规则 | 高 | 大（需引入引擎） | 高 | 下一阶段 |
| 正交架构 | 高 | 大（需重构目录） | 中 | 伴随组件拆分 |
| 管道过滤器 | 中（仅排课） | 小 | 高 | 局部采用 |
| SOA | 中（后端） | 大 | 低 | 远期 |
| 微服务 | 低 | 极大 | 低 | **否决** |
| C2 | 低 | 中 | 低 | 否决 |
| 黑板 | 低 | 大 | 低 | 否决 |
| 面向 Agent | 极低 | 极大 | 极低 | **否决** |
| HMB | 极低 | 极大 | 极低 | **否决** |

### 1.2 关键否决理由

- **微服务**：用户量 < 10K、单团队、选课扣库存是强一致性事务——分布式拆分反而引入分布式事务问题，ROI 为负
- **面向 Agent**：协商/拍卖式选课概念吸引力 > 工程价值；当前 HTTP 请求式选课已满足需求，Agent 建模无真实用户需求驱动
- **HMB**：层次消息总线用于分布式异构构件互联，本系统无跨组织集成、无异构中间件

### 1.3 选择事件驱动的 5 个理由

1. **业务本质是事件链**：教师申报 → 管理员审核 → 排课发布 → 学生选课/退课 → 系统重置 → 回到待排课。天然是 `Event₁ → Event₂ → Event₃` 的因果链
2. **当前同步耦合过紧**：`handleSelect()` 成功后手动调用 3 个 fetch（`fetchMyCourses` / `fetchAvailableCourses` / `fetchCourses`），发布-订阅模型天然解耦这种"动作 → N 个反应"
3. **异步扩展需求明确**：选课后需要通知（站内信/邮件）、审计日志、数据仓库同步——都是异步非关键路径，事件驱动让主流程不被拖慢
4. **向前兼容组件拆分**：当 `App.vue` 拆成多个页面组件后，mitt 事件总线保证组件间通信不退化
5. **后端 Spring 原生支持**：`ApplicationEventPublisher` + `@EventListener` + `@Async` 三者已内置，引入成本为零

## 二、事件的组件 (Components)

组件是事件驱动架构中的**计算单元**，分为三类：事件源 (Event Source)、事件总线 (Event Bus)、事件消费者 (Event Consumer / Listener)。

### 2.1 前端组件树

```
┌─────────────────────────────────────────────────────────┐
│                    mitt Event Bus                       │
│                  (frontend/src/utils/eventBus.js)        │
└──────┬──────────┬──────────┬──────────┬─────────────────┘
       │          │          │          │
  ┌────▼────┐ ┌───▼────┐ ┌───▼────┐ ┌──▼──────────┐
  │ Event   │ │ Event  │ │ Event  │ │ Event        │
  │ Source  │ │ Source │ │ Source │ │ Source ...   │
  │         │ │        │ │        │ │              │
  │ handle  │ │ handle │ │ submit │ │ handleReset  │
  │ Select  │ │ Drop   │ │Proposal│ │ System       │
  └─────────┘ └────────┘ └────────┘ └──────────────┘
       │          │          │          │
       ▼          ▼          ▼          ▼
  ┌─────────────────────────────────────────────────────┐
  │               Event Consumers (Listeners)            │
  │  ┌──────────┐ ┌──────────┐ ┌──────────┐             │
  │  │ on(SEL)  │ │ on(DROP) │ │on(RESET) │ ...         │
  │  │ → fetch* │ │ → fetch* │ │ → init   │             │
  │  └──────────┘ └──────────┘ └──────────┘             │
  └─────────────────────────────────────────────────────┘
```

**设计要点**：
- **单总线实例**：整个前端共用一个 `mitt()` 实例，通过 `import { bus }` 单例注入
- **事件源不感知消费者**：`handleSelect` 只知道 `bus.emit(COURSE_SELECTED, payload)`，不知道谁会响应
- **消费者关注自己的数据域**：选课 listener 刷新课表+库存；审核 listener 刷新课程列表；互不干扰

### 2.2 后端组件树

```
┌──────────────────────────────────────────────────────────┐
│           Spring ApplicationEventPublisher               │
│              (Spring 容器内置，单例)                       │
└──────┬──────────┬──────────┬──────────┬──────────────────┘
       │          │          │          │
  ┌────▼────┐ ┌───▼────┐ ┌───▼────┐ ┌──▼────────────┐
  │CourseSel│ │CourseDr│ │CourseAu│ │ScheduleGen    │
  │ectedEvt │ │oppedEvt│ │ditedEvt│ │eratedEvent    │... 
  │(Source: │ │(Source:│ │(Source:│ │(Source:       │
  │ Service)│ │Service)│ │Ctrl)   │ │Controller)    │
  └─────────┘ └────────┘ └────────┘ └───────────────┘
       │          │          │          │
       ▼          ▼          ▼          ▼
  ┌──────────────────────────────────────────────────────┐
  │          CourseEventListener (@Async)                 │
  │  ┌──────────────┐ ┌──────────────┐ ┌──────────────┐  │
  │  │ onCourseSel  │ │ onCourseDrop │ │ onSysReset   │  │
  │  │ → log.info() │ │ → log.info() │ │ → log.info() │  │
  │  └──────────────┘ └──────────────┘ └──────────────┘  │
  └──────────────────────────────────────────────────────┘
```

**设计要点**：
- **事件继承 `ApplicationEvent`**：利用 Spring 的类型匹配自动路由到正确的 `@EventListener` 方法
- **发布器封装**：`CourseEventPublisher` 是 Facade，对外暴露 6 个类型安全的发布方法，隐藏 `publisher.publishEvent(new XxxEvent(this, ...))` 的样板代码
- **监听器异步**：`@Async` + `@EnableAsync` 保证日志/审计不阻塞主事务

### 2.3 组件接口规格

| 组件 | 接口（输入） | 接口（输出） | 状态管理 |
|---|---|---|---|
| `EventBus (mitt)` | `emit(type, payload)` | 广播给所有 `on(type, handler)` | 无状态（纯消息路由） |
| `EventPublisher (Spring)` | `courseSelected(...)` 等 6 个方法 | `ApplicationEvent` 实例 | 无状态 |
| `EventListener` | `ApplicationEvent` 实例 | 日志输出（可扩展为 WS/DB） | 无状态 |
| `handleSelect` (Event Source) | UI 点击事件 + API 响应 | `COURSE_SELECTED` 事件 | 发布后不持有事件引用 |
| `on(COURSE_SELECTED)` (Consumer) | `{ courseId, course }` payload | 调用 fetch*() 刷新 UI | 无内部状态 |

## 三、事件的连接件 (Connectors)

连接件定义组件之间**如何交互**——通信协议、数据格式、时序。

### 3.1 前端连接件：mitt 内存事件总线

```
连接件类型：内存中的发布-订阅通道 (In-Memory Pub/Sub)
────────────────────────────────────────────────────────
实现          mitt@3.0.1 (288 bytes gzipped)
拓扑          星形 (star) — 事件源 → 总线 → N 个消费者
传递语义      即发即忘 (fire-and-forget)，同步执行
序列化        无 — JavaScript 对象引用传递
生命周期      应用级 (App.vue onMounted → onUnmounted)
可靠性        无持久化，页面刷新后事件丢失（符合 SPA 预期）
```

**连接件约束**：
- **C1**：emit 必须在 Vue 响应式上下文中调用（`setup` 内），不能跨 Worker/iframe
- **C2**：payload 必须是可序列化的 Plain Object（避免传 DOM 节点、函数、循环引用）
- **C3**：listener 内禁止抛未捕获异常（mitt 不会吞异常，会中断后续 listener）

### 3.2 后端连接件：Spring ApplicationEvent 机制

```
连接件类型：应用容器内的事件广播 (In-Process Event Broadcast)
────────────────────────────────────────────────────────
实现         Spring ApplicationEventPublisher (接口)
             + SimpleApplicationEventMulticaster (默认实现)
拓扑         星形 (star) — Publisher → Multicaster → N 个 @EventListener
传递语义     同步发布，异步消费 (@Async 线程池隔离)
序列化       无 — Java 对象引用传递（单 JVM 内）
生命周期     Spring 容器级 (随 ApplicationContext 初始化)
可靠性       Spring 事务内发布 —— 若需要事务提交后发布，
             可用 @TransactionalEventListener(phase = AFTER_COMMIT)
```

**连接件约束**：
- **C4**：事件类必须继承 `ApplicationEvent`
- **C5**：监听方法签名必须精确匹配事件类型（Spring 按参数类型路由）
- **C6**：异步监听器异常不会传播回发布者（`SimpleAsyncTaskExecutor` 默认吞异常）

### 3.3 前后端连接件：HTTP (保持不变)

事件驱动改造**未改变前后端通信协议**——选课请求仍然走 `POST /course/select`，区别在于：
- **Before**：前端收到 HTTP 200 → 直接调 3 个 fetch → UI 更新
- **After**：前端收到 HTTP 200 → `bus.emit()` → 3 个 listener 各自调 fetch → UI 更新

HTTP 连接件在当前阶段保持不变，作为事件的**外部触发器**存在。未来 WebSocket 将作为后端事件的**推送连接件**补充进来（第 2 阶段）。

### 3.4 连接件对比

| 维度 | mitt (前端) | Spring Event (后端) | HTTP (前后端) |
|---|---|---|---|
| 类型 | Pub/Sub | Pub/Sub | Request/Reply |
| 范围 | 浏览器 Tab | JVM 进程 | 跨进程 |
| 延迟 | < 1μs | < 1ms | 10-500ms |
| 可靠性 | 无保证 | Spring 容器保证 | HTTP 状态码 |
| 用途 | 组件解耦 | 服务解耦 | 触发事件 |

## 四、事件的约束 (Constraints)

事件驱动架构的核心约束定义了**什么是合法的事件、如何发布、如何消费**。

### 4.1 事件命名约束

| 约束 ID | 内容 | 违反后果 |
|---|---|---|
| **N1** | 事件名用 `domain:verb-past-tense` 格式，如 `course:selected` | 命名混乱，无法按域分组 |
| **N2** | 每个业务动作对应一个事件类型，不合并（如 `course:selected` 和 `course:dropped` 分开） | 消费者需额外判断，丢失类型安全 |
| **N3** | 事件名定义为常量 (`COURSE_SELECTED`)，禁止魔法字符串 | 拼写错误不报编译错 |

### 4.2 事件 Payload 约束

| 约束 ID | 内容 | 违反后果 |
|---|---|---|
| **P1** | Payload 只携带**不可变标识符** (ID) + **快照数据**，不携带可变对象引用 | 消费者修改 payload 影响其他消费者 |
| **P2** | Payload 最小化：只传消费者**已知需要**的字段（如 `{ courseId, course }`），不传整个 `appState` | 紧耦合，换字段牵连全局 |
| **P3** | 后端事件 Payload 通过 getter 暴露，字段 `private final` | 事件被中途篡改 |

### 4.3 发布-消费时序约束

| 约束 ID | 内容 | 违反后果 |
|---|---|---|
| **T1** | 先改状态，后发事件（DB 写入成功 → emit） | 消费者读到旧数据 |
| **T2** | 事件发布必须在 try-catch **内**、成功分支**末尾** | 失败路径误发成功事件 |
| **T3** | 监听器不反调发布者（禁止 `emit → listener → emit` 循环） | 无限递归 / 死循环 |

### 4.4 生命周期约束

| 约束 ID | 内容 | 违反后果 |
|---|---|---|
| **L1** | 前端：`onMounted` 注册 listeners，`onUnmounted` 解注册 | 内存泄漏 / 重复注册 |
| **L2** | 后端：`@EventListener` 随 Spring Bean 生命周期，无需手动管理 | —（Spring 自动保障） |
| **L3** | 事件对象创建后即不可变，发布后立即丢弃引用 | 事件被复用/篡改 |

### 4.5 约束检查清单（验证方法）

```
□ N1-N3: grep 'bus.emit' App.vue    → 全部使用常量 ✓
□ P1-P3: 后端 Event 类字段均为 private final ✓
□ T1:    事件发布在 res.data.code === 200 分支内 ✓
□ T2:    事件发布在 API 成功回调内，非 finally ✓
□ T3:    listener 内部只调 fetch*()，不 emit ✓
□ L1:    onUnmounted 解注册 8 个事件 ✓
□ L2:    CourseEventListener 标记 @Component ✓
```

## 五、各架构元素详细设计

### 5.1 前端事件总线：`eventBus.js`

```javascript
// 文件: frontend/src/utils/eventBus.js
// 架构角色: 连接件 — 内存发布-订阅通道
// 技术选型: mitt (Vue 3 官方推荐的事件总线替代方案，288 bytes)
//
// 设计决策:
//   - 不创建多个 bus 实例: 单总线 = 全局命名空间，避免跨 bus 的事件丢失
//   - 不通过 provide/inject 传递: 非组件代码（api 层、utils）也需要 emit/on
//   - 不选 Vuex/Pinia plugin: 事件 ≠ 状态，不需要 devtools 追踪

import mitt from 'mitt'
export const bus = mitt()
export default bus
```

### 5.2 前端事件类型定义：`eventTypes.js`

```javascript
// 文件: frontend/src/events/eventTypes.js
// 架构角色: 约束定义 — 事件命名空间
//
// 命名规范: DOMAIN:VERB (过去式，表示"已发生")
//   - COURSE_SELECTED 而非 SELECT_COURSE (命令式 → 事件式思维转变)
//
// 分组原则:
//   - course:*   → 课程域（选/退/申报/审核/排课）
//   - system:*   → 系统级（重置）
//   - auth:*     → 认证域（登录/登出）
//   - data:*     → 通用数据刷新（消费者自行判断是否需要响应）
```

```
    + onCourseAudited(CourseAuditedEvent)
    + onScheduleGenerated(ScheduleGeneratedEvent)
    + onSystemReset(SystemResetEvent)
```

**为何用 Publisher Facade 而非直接注入 ApplicationEventPublisher？**
1. 类型安全：`publisher.courseSelected(1L, 7L, "算法", 29)` 编译期检查参数类型
2. 单一入口：未来加 AOP 环绕日志、消息队列桥接只需改 Publisher 一处
3. 可测试：Mock `CourseEventPublisher` 比 Mock `ApplicationEventPublisher` 语义更清晰

### 5.4 异步配置设计

```java
// 文件: backend/.../config/AsyncConfig.java
// 架构角色: 基础设施 — 为事件监听器提供独立线程池
//
// 为什么 @Async 而非同步？
//   事件监听器（日志、审计、未来 WebSocket 推送）属于"非关键路径"
//   - 同步：主事务等待日志写入 → 选课 RT +10ms
//   - 异步：主事务直接返回 → 选课 RT 不受影响
//
// 风险：异步监听器异常会丢失（SimpleAsyncTaskExecutor 默认行为）
// 缓解：生产环境配置 ThreadPoolTaskExecutor + 自定义 RejectedExecutionHandler
```

### 5.5 前端 Handler Before/After 设计对比

以 `handleSelect` 为例说明为何这样重构是"正确的解耦"：

**Before（紧耦合）**：
```
handleSelect → API call → success?
  ├── push to myCourseList      ← 状态变更 1
  ├── fetchMyCourses()          ← 副作用 1 (覆盖状态变更 1)
  ├── fetchAvailableCourses()   ← 副作用 2
  └── fetchCourses()            ← 副作用 3
```
问题：handler 必须知道"选课后要更新哪些数据"——违反了单一职责。

**After（发布-订阅解耦）**：
```
handleSelect → API call → success?
  └── bus.emit(COURSE_SELECTED, { courseId, course })

Listener 1: on(COURSE_SELECTED) → fetchMyCourses()
Listener 2: on(COURSE_SELECTED) → fetchAvailableCourses()  [复用同一个 listener]
Listener 3: on(COURSE_SELECTED) → fetchCourses()
```
效果：加新副作用（如"选课后刷新仪表盘数字"）只需加一个 listener，不动 handler。

### 5.6 事件类型与 Handler 映射表

| 前端事件 | 发射位置 | Payload | 消费者动作 |

## 六、事件拓扑与流转

### 6.1 完整事件流转图（端到端）

```
┌── 浏览器 ──────────────────────────────────── 服务器 JVM ──┐
│                                                           │
│  [学生点击"抢课"]                                          │
│       │                                                    │
│       ▼                                                    │
│  handleSelect(course)                                      │
│       │                                                    │
│       ├─ axios.post(/course/select?courseId=)  ──────────→ │
│       │                                                    │
│       │              HTTP Request ─────────────────→       │
│       │                                        CourseController
│       │                                              │
```

### 6.2 时序约束

```
T₀: 用户点击选课按钮
T₁: HTTP POST /course/select 发出
T₂: 后端开始处理 (Redis 预减库存、冲突检测、DB 写入)
T₃: 后端 publishEvent (同步，< 1μs)
T₄: 后端 return HTTP 200
T₅: 前端收到 200，bus.emit(COURSE_SELECTED)
T₆: 3 个 listener 依次执行，各发 HTTP GET
T₇: UI 全部刷新

关键路径: T₀ → T₇ ≈ T₁→T₄ + T₅→T₇ (网络 RTT × 1 + 网络 RTT × 3)
异步路径: T₃' → 日志写入 (与 T₄→T₇ 并行，不增加关键路径)
```

### 6.3 失败模式分析

| 失败场景 | 前端行为 | 后端行为 | 恢复策略 |
|---|---|---|---|
| API 返回非 200 | 不 emit，弹错误 | 不 publishEvent | 用户重试 |
| 前端 emit 后，listener fetch 失败 | `ElMessage.error`（各自 catch） | — | 手动刷新按钮 |
| 后端 publishEvent 后，监听器抛异常 | — | `@Async` 吞异常（不传播） | 日志中可见 |
| 页面刷新 | 所有 listener 解注册 + 重新注册 | — | `onMounted` 重新初始化 |
| 后端重启 | 前端 401 → 跳登录 | 未消费的事件丢失 | 用户重新登录 |

## 七、与其他风格的协同

事件驱动风格不排斥其他风格——在多风格异构系统中，事件驱动作为**通信与解耦机制**与其他风格配合：

### 7.1 事件驱动 + AOP（已协同）

```
AOP 横切关注点:
  axios interceptor (已有) ── 挂 token ──→ 所有 API 调用

事件驱动叠加:
  bus.emit(COURSE_SELECTED) ── 触发 AOP 效果:
    ├── interceptor 自动挂 token
    ├── 统一 401 处理（已有）
    └── 统一错误 toast（已有）
```

### 7.2 事件驱动 + 基于规则（未来协同）

```
Drools 规则引擎监听 CourseSelectedEvent:
  when: sum(student.selectedCourses.credit) + newCourse.credit > 30
  then: reject + 自动退课 + emit CreditExceededEvent

前端监听 CreditExceededEvent:
  → ElMessage.error("超过学分上限")
```

### 7.3 事件驱动 + 管道过滤器（排课局部协同）

```
autoSchedule() 内部管道:
  [课程列表] → [过滤 status=1] → [教师偏好排序] → [教室匹配]
     → [冲突检测] → [写入 DB]

管道末端:
  eventPublisher.scheduleGenerated(count)
     → 前端刷新课程列表
     → 审计日志
```

### 7.4 事件驱动 + SOA（远期协同）

```
当前（单体）:
  CourseServiceImpl ──publishEvent──→ CourseEventListener (同 JVM)

远期（粗粒度 SOA）:
  CourseServiceImpl ──publishEvent──→ Kafka ──→ NotificationService (独立进程)
                                             ──→ AuditService (独立进程)
```
